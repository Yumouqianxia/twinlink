# TwinLink 私有服务器部署记录

日期：2026-10-31（Asia/Shanghai）。

## 已部署

已部署实例为私有海外节点，Debian 13 / x86_64，约 1 GiB
内存，部署前约 17 GiB 可用磁盘。保留原有 SSH 和 443 服务。

| 服务 | 入口 | 用途 |
|---|---|---|
| twinlink-net.service | TCP/UDP 11010 | EasyTier 发现与中继 |
| twinlink-mailbox.service | HTTPS 18443 | 密文消息与文件暂存 |
| EasyTier 管理 RPC | 127.0.0.1:15888 | 仅服务器本机管理 |

两项服务使用各自的无登录系统用户，设为开机自启、失败重启，配置内存/线程
限制。未安装 Docker、未关闭防火墙、未修改 SSH 或占用原有 443 端口。
UFW 只增加 11010/TCP、11010/UDP、18443/TCP 的对应规则。

EasyTier 使用官方独立分发的 **v2.6.4**，Linux x86_64 归档 SHA-256 已与
官方 Release 元数据核对：
`61b659eaedba658fa66fe47d17e1426cdd77e5d02fa15fed447bb4357c09dfd6`。
不创建服务器系统虚拟网卡。转发白名单限定到部署时随机生成的私有命名空间，
没有使用开放的 `*` 公共转发白名单。网络命名空间只放在私有配置/邀请中。

## 暂存服务

源码 `server/mailbox.py`，仅使用 Python 标准库。它保存密文，不解密消息、
不运行上传内容，也不提供远程文件系统浏览。消息、文件名和原始内容哈希均由
客户端封装加密后上传；服务端只能看到队列/文件标识、角色、密文大小和时间。
HTTPS 另外校验证书、主机身份，授权令牌不放在 URL 中。

默认上限：单文件 1 GiB、所有附件合计预留 4 GiB、事件队列 32 MiB /
4096 条、128 个房间。保留 7 天，后台每分钟清理过期内容；没有消息/附件且闲置超过保留期的
空房间也会清理，避免永久占用房间配额。活跃房间会刷新活动时间。
本地聊天记录不会
因此删除。上传按 1 MiB 明文对应的密文块保存，支持重复提交和缺块续传。
只有完整上传后文件才可下载；客户端还必须执行用户确认接收与落盘校验。

服务器配置与令牌：`/etc/twinlink/`，没有写入代码仓库或本说明。
服务器叶证书私钥：`/etc/twinlink/tls/key.pem`，仅专用服务用户可读。
叶证书包含该服务器 IP 的 SAN，`CA:FALSE` / `serverAuth`，有效期至
**2027-10-31 12:26（北京时间）**，需要在到期前续签。
叶证书 SHA-256 指纹：
`1A:52:DB:4E:AE:B5:C1:5E:27:98:EF:0C:6F:96:EF:C7:3D:42:AE:43:91:2B:94:7C:B5:9D:87:18:D0:40:61:94`。

独立 CA 位于 `/etc/twinlink/ca-cert.pem`，CA 私钥
`/etc/twinlink/ca-key.pem` 只允许 root 读取，服务账号不能签发证书。
当前 CA 有效期至 **2028-10-30（北京时间）**，指纹保持为：
`7B:01:7C:F5:CD:F1:96:F9:3E:0F:05:0D:D2:7C:72:39:5E:C8:56:25:F9:B9:0E:B2:E8:06:74:FB:E4:11:51:BF`。
客户端设置码信任的是 CA，不应把服务器叶证书作为 CA 分发。同一 CA 续签
服务器证书不需要改变设置码；更换 CA 时需要重新分发可信配置。

初次部署曾直接使用 `CA:TRUE` 的自签证书作为服务器证书：Python/OpenSSL
检查通过，但实际 Rust/rustls 检查返回 `CaUsedAsEndEntity`。现已保留原 CA，
签发独立叶证书并部署。实际 Rust 客户端公网检查已通过；错误 CA、错误主机名
均被拒绝，没有关闭证书或主机名校验。部署脚本已包含这次迁移和叶证书续签逻辑。

本机私有服务器设置码及配置位于
`~/.local/share/twinlink-work/deployment/`（目录 0700、配置 0600）。设置码
包含访问凭据，不属于公开配置。Mac 原生 app-data 中已预置服务器配置，未
创建房间、未生成/公开真实配对 Key。SSH 密码不写入项目或部署脚本。

部署脚本：`scripts/deploy-server.sh`。在服务器上和经过审阅的 `mailbox.py`
放在同一临时目录后以 root 运行；脚本从官方源下载并核验引擎，保留已经生成
的服务器设置、证书与持久化数据。应用层协议见 `SERVER-PROTOCOL.md`。

## 实际验收

- `python3 -m unittest discover -s server -v`：6 项通过，覆盖鉴权/房间隔离、
  幂等提交/显式确认、分块续传与篡改检测、配额预留/过期清理、输入边界，
  以及闲置空房间回收/活跃和有待收数据房间保留。
- 从这台 Mac 直接访问服务器公网 HTTPS 入口，使用提供的 CA 校验及 IP 主机
  校验通过；错误服务令牌返回 401，错误房间令牌返回 403。
- 实际上传、部分中断后续传、下载并在接收端解密校验约 8 MiB 生成的测试
  数据。上传约 12.31 s、下载约 13.76 s，包含请求/握手开销；不是带宽承诺。
  同时验证了密文事件存储、重复消息去重、确认后移除，以及文件删除。
- 同一台 Mac 上启动两份真实 EasyTier 2.6.4 进程，禁用普通自动 P2P，均连接
  海外节点。授权命名空间下约 3.73 s 后完成 TCP 回显；非授权网络回显超时，
  确认中继白名单生效。测试结束均清理子进程，没有创建 TUN。
- 使用实际 Rust `MailboxClient`（reqwest/rustls）直接连接公网入口，房间注册、
  密文事件重复提交/解密/确认、约 1 MiB 分片文件缺块补传/完整后下载/解密、
  空文件与删除均通过。该检查隔离了 HTTP/加密模块，不等于完整 Core 崩溃恢复
  或 UI 验收；错误 CA 与错误主机名负例也被 TLS 拒绝。
- systemd 检查两项新服务与原有 443 服务均处于 active。

上述两端测试均由同一台 Mac 发起，**不等于两台独立电脑/不同运营商打洞测试**，
也不等于客户端 UI、游戏 LAN 或 TUN 权限流程已通过。本文件只记录服务端与
网络入口的已执行检查；客户端状态另见 `CLIENT-VALIDATION.md`。

## 维护与回退

查看：`systemctl status twinlink-net twinlink-mailbox`；日志通过
`journalctl -u twinlink-net -u twinlink-mailbox` 查看，不输出令牌或正文。
停用可用 `systemctl disable --now twinlink-net twinlink-mailbox`，不会清除数据。
回退时只撤销这次新增的三条 UFW 服务规则，保留 SSH 和原有服务；不要全局
重置防火墙。`/var/lib/twinlink-mailbox` 包含持久化队列及附件，删除前需明确
确认业务数据可丢弃。TLS 叶证书更新后应重启服务；只有 CA 更换才需更新客户端可信配置。
请在叶证书到期前用部署脚本续签（剩余不足 30 天时生成新叶证书），并在 CA
到期前规划 CA 更新与设置码重新分发。
