# 聊天附件与图片预览

输入框左下角有「文件」与「图片」两个独立入口。图片入口只选择 PNG、JPEG、GIF、WebP；它们与普通文件使用同一套传输机制。桌面端拖入文件也会在聊天中生成附件卡片，发送后保留当前页面。

文件记录与文字按创建时间交错显示，进度和状态更新不会改变位置；记录保存在本地数据库，刷新和重启后仍可见。旧记录优先使用本地上传/下载元数据回填时间，确实没有时间的记录显示为「早期文件记录」，不会假定是刚发送的。备份兼容旧格式，新备份保留附件时间，仍不包含文件本体或路径。

聊天里的附件卡片与文件传输页使用相同的状态和操作。对方发来的文件须确认接收；设置中的自动接收规则保持生效。仅邀请到达、服务器暂存完成或发送字节完成都不等于对方已接收。

本机发出的图片在源文件仍存在时可预览；收到的图片须接收并保存完成后才可预览。点击缩略图在应用内放大，关闭按钮或 Escape 退出。当前房间变化会关闭预览并清除旧画面。文件被移动、删除，或格式不受支持时显示普通附件和提示，不会为了预览自动下载。

图片预览上限为 20 MiB、单边 16,384 像素、总计 4,000 万像素，适用于 PNG/JPEG/GIF/WebP。此限制只针对内置预览，P2P 原文件发送仍无应用大小上限；离线暂存仍沿用原来的 1 GiB 限制。

## 实现边界

- 图片字节走 `twinlink-preview` 自定义 URI scheme，不经过前端 IPC、Base64 或公共文件服务。
- URL 仅含房间和传输 UUID，核心按当前房间查询持久化记录；没有任意路径读取接口，也没有扩大文件系统权限。
- 核心的直连与离线发送入口在登记前规范化所选路径，因此显式选择的符号链接会绑定到当时的真实文件；路径无法读取时明确报错。
- 接收文件只能读取已完成记录的实际发布路径，并检查接收目录（发布路径先规范化，父目录必须等于规范化的接收目录）、普通文件、符号链接、大小、图片魔数和尺寸。备份导入的历史没有源文件访问记录，因此不能借备份读取本机任意文件。
- 响应禁止缓存、禁止 MIME 嗅探，无通配 CORS。适配器限制主窗口、GET 方法、无查询串和本地应用来源；`tauri.conf.json` 的 CSP `img-src` 增加 `twinlink-preview:` 及 Windows 上的 `http(s)://twinlink-preview.localhost` 形式。
- 时间线按条目 key 复用 DOM，进度更新保留缩略图节点，避免图片读取风暴；只有预览 URL 变化时才替换媒体节点。进度更新不会把正在阅读旧记录的用户拉到底部；新发送的内容会滚到最新位置，读取更早记录时保持滚动锚点。

## 本轮验证

验证包含真实核心回环传输与隔离的浏览器界面回归。所选符号链接在邀请发出后即使改指向，也不会改变本次发送的源文件；界面测试等待图片实际解码完成后再检查尺寸。

- `pnpm build`：通过。
- `cargo test -p twinlink-core --locked`：本机 71 通过，1 个原有忽略项。覆盖真实回环传输、接收前后预览授权、缺失本地文件记录的备份、房间切换、符号链接及所选链接的源文件绑定、假图片、尺寸/字节上限，以及旧时间回填与进度不重排。
- `cargo test -p twinlink --locked`：5 通过，含预览请求标识/来源/方法及响应头校验。
- `cargo check -p twinlink --locked`：通过。
- `tests/attachments_ui.py`：通过。使用明确的 IPC/图片响应测试夹具，覆盖聊天排序、操作、两个选择入口、弹窗、错误退化、缩略图复用、滚动、房间清理，以及实际浏览器预览的按钮对齐与禁用状态。
- `scripts/test_file_ui.py`、`tests/theme_plugins_ui.py`、`tests/updates_ui.py`：通过，分别回归拖拽/备份/自动接收、主题与更新提示。

以上浏览器界面测试使用 Chromium headless，不代表 Windows/macOS 原生文件选择器或原生 WebView 图片 scheme 已实测；真实回环核心测试不代表跨公网或 EasyTier 直连已实测。原生双机验收应分别测试 Windows 与 macOS 发图、接收前不可预览、接收后放大、重启后记录/图片，以及断线离线暂存。
