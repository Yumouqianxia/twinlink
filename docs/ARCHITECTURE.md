# 同频 / TwinLink：工程与存储结构

本文件说明当前工程边界与协议约束。具体已执行检查以 `CLIENT-VALIDATION.md`
和 `SERVER-DEPLOYMENT.md` 为准，不把协议设计当作已完成的跨网络测试。

## 代码边界

| 位置 | 职责 |
|---|---|
| `src/main.ts`、`src/styles.css` | 中文界面、元数据展示、用户交互 |
| `src/api.ts` | Tauri IPC 类型、事件、用户主动选择文件/目录 |
| `src-tauri/src/main.rs` | 薄命令适配、原生启动与退出、事件转发 |
| `crates/twinlink-core` | 配对、网络监督、消息与文件生命周期、持久化 |
| `crates/twinlink-core/src/pairing.rs` | 设置码/配对码、参数校验、用途隔离的派生 |
| `crates/twinlink-core/src/network.rs` | 独立 EasyTier 子进程与 loopback 转发 |
| `crates/twinlink-core/src/wire.rs` | 有界应用帧、随机挑战认证 |
| `crates/twinlink-core/src/mailbox.rs` | 与私有 HTTPS 信箱的协议边界 |
| `crates/twinlink-core/src/storage.rs` | SQLite 消息、发送队列及传输元数据 |
| `server/mailbox.py` | 服务器密文队列、分块对象、配额与清理 |
| `scripts` | 引擎下载校验、私有服务器部署 |

网络打洞、路径选择和中继由 EasyTier 完成。没有把 EasyTier Rust 源码链接到
本项目，没有自己实现 NAT 穿透。界面不接收大文件数据，只接收进度与元数据。

## 配对

管理员设置码 `TL-SRV1.` 携带经过验证的服务器配置（中继 URL、HTTPS 信箱 URL、
可信 CA、访问令牌、私有网络前缀）。房间配对码 `TL1.` 携带版本、随机的 32 字节
种子与服务器配置；它是持有者凭据，Base64url 只是编码，不提供保密性。

创建端从操作系统随机源生成种子；加入端从同一码派生相同的网络名和密钥。
网络身份、网络密钥、私有虚拟地址使用带版本和用途标签的 HMAC-SHA256 派生。
双方角色固定为 host/join，自动取得同一子网的 `.1` 与 `.2`，无需输入对方 IP。
配对码中的未知字段、异常地址、角色和长度在启动引擎之前被拒绝。

完整配对码只通过明确的导出/复制操作返回，快照和普通事件不包含种子、令牌
或证书。当前采用共享房间秘密，只面向两人；没有设备公钥白名单或多人踢出。

## 网络与在线状态

```text
中文界面 → Tauri IPC → Rust core → loopback TCP → 独立 EasyTier
                                                       ↕
                                           自动直连 / 私有服务器中继
                                                       ↕
对方界面 ← Tauri 事件 ← Rust core ← loopback TCP ← 对方 EasyTier

Rust core ← 已验证身份的 HTTPS → 私有密文信箱 ← HTTPS → 对方 Rust core
```

免 TUN 模式使用 `--no-tun true --use-smoltcp true`，不建立系统虚拟网卡。
本机应用服务监听 `127.0.0.1:29741`，EasyTier 本地转发与管理 RPC 各使用独立的
loopback 动态端口。TCP 白名单限制为应用服务端口，不添加子网代理或修改 DNS。
不继承外部 `ET_*` 环境设置，以免扩大本次进程的网络范围。

应用层挑战握手成功才显示对方已连接，EasyTier 进程启动或信箱可用均不等于
对方在线。`route` 在没有实际 EasyTier RPC/CLI 数据时为 `unknown`，界面不根据
延迟或消息成功猜测“直连/中继”。断开后的重试由单一监督任务持有，房间更换、
暂停和退出时取消旧任务并回收引擎进程。

当前虚拟地址只用于应用内部网络。局域网游戏需要真实 TUN 及相应的管理员
授权流程，不能把免 TUN 的聊天连接宣称为已经完成的游戏 LAN。

## HTTPS 信箱约束

精确协议见 `SERVER-PROTOCOL.md`。信箱与 EasyTier 服务独立：只要已配对且
信箱可达，发送消息不应要求对方的实时通道在线。

HTTPS 保持证书链和主机名校验，只额外信任设置码提供的 CA，拒绝明文 HTTP
与重定向。访问令牌和房间令牌只放在敏感请求头中，不在 URL、日志或前端保存。
消息内容和附件元数据使用 XChaCha20Poly1305；AAD 绑定房间、角色和事件 ID。

本地发送队列在首次 POST 前持久化密文，重试使用完全相同的事件 ID 与密文。
“服务器已存”只表示服务器已提交事务；“对方已收到”需要对方持久化后返回的
认证确认。接收方按消息 ID 对实时通道与信箱事件去重。服务器 7 天保留期不代表
本机历史会被删除，也不代表消息自动已读。

## 文件约束

- 发送源只能来自用户显式选择的普通文件，不提供远程文件系统浏览。
- 信箱附件上限 1 GiB，按 1 MiB 明文块加密，单块增加 16 字节认证标签。
- 每个文件 ID 对应不可变内容。上传前完成加密副本并核对总哈希，重试从副本
  读取相同字节，避免源文件变化后复用密钥/nonce。
- 服务器以 UUID 存储密文，未加密清单不含源文件名、远程路径或明文哈希。
- 完整上传后才发布加密的文件邀请；服务器清单记录已提交分块，支持缺块续传。
- 收到邀请不代表同意。用户确认前，不下载密文块或在接收目录写入内容。
- 接受后流式解密，每块验证 tag，最终核对总大小和 SHA-256；使用本机独占
  临时文件与不覆盖提交，已有同名文件自动改名。
- 取消、拒绝、过期和校验失败均不能成为完成状态。只有成功保存及认证完成确认
  才能让发送方显示完成；具体实现与测试范围以客户端验证记录为准。

## 本地与服务器文件

macOS 应用数据通常位于
`~/Library/Application Support/app.twinlink.desktop/`；Windows 通常位于
`%APPDATA%/app.twinlink.desktop/`，以 Tauri 系统路径 API 为准。

```text
应用数据目录/
├─ app-state.json        私有服务器设置、房间种子、暂停状态
├─ twinlink.db           聊天记录、发送队列及传输元数据
├─ twinlink.db-wal       SQLite 事务日志
├─ twinlink.db-shm       SQLite 共享内存索引
├─ engine-state/         EasyTier 节点状态
└─ 附件加密副本/          用于重试的本地缓存，实际位置由 core 定义

用户下载目录/TwinLink/    默认接收目录，可在设置更改
├─ .twinlink-随机名.part   同意后创建的临时文件
├─ 报告.pdf              验证完成后的文件
└─ 报告 (1).pdf          已有同名文件时自动改名
```

Unix 上私有数据目录 0700、凭据/数据库 0600。SQLite 的本机聊天记录目前不做
静态加密；拥有本机用户权限的人也可能读取子进程环境中的 EasyTier 网络秘密。
“忘记房间”清除连接配置，不是删除历史记录；清理本地数据需要另行处理。

服务器只保存密文与路由元数据。默认保留 7 天、附件总预留 4 GiB、事件队列
32 MiB/4096 条、128 个房间，每分钟清理到期对象。部署账号、令牌和私钥在
仓库外，访问凭据不包含在构建产物或公共说明中。
